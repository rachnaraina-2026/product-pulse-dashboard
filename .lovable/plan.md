# Product Feedback Synthesis Dashboard

A PM-facing analytics console that turns raw support tickets, emails, and Slack messages into a synthesized feedback report. Runs on realistic mock data; the synthesis narrative is generated by Lovable AI.

## Layout

```text
┌────────────────┬──────────────────────────────────────────┐
│ SIDE PANEL     │ MAIN — Summary                           │
│ Products       │  KPI row · category breakdown ·          │
│ Customers      │  top requested features · urgent callouts│
│ Date range     │  Summary / Long-form toggle              │
│ Cadence        ├──────────────────────────────────────────┤
│ [Run synthesis]│ MAIN — Evidence table                    │
│                │  customer · category · description ·     │
│                │  churn risk · confidence · citation      │
└────────────────┴──────────────────────────────────────────┘
```

## Side panel

- **Products** — multi-select with "All products"; grouped by product line, so a PM can pick one line, several, or everything.
- **Customers** — multi-select with "All customers", searchable.
- **Date range** — presets (Last 7/30/90 days, Quarter to date) plus a custom range picker. Defaults to last 30 days ending today, so stale feedback is excluded.
- **Cadence** — schedule builder: Off / Weekly (pick weekday) / Monthly (pick day of month) / Custom, plus delivery time. Saved schedules list with enable-disable and "next run" label. UI-only in this version: nothing executes on a server timer.
- **Run synthesis now** — on-demand trigger; shows generating state and a "last run" timestamp.

## Main panel — top: synthesis

Two presentation modes via a toggle:

- **Summary** — KPI tiles (total feedback items, unique customers, at-risk accounts, avg confidence); breakdown by category (Customer Satisfaction, Bug, New Feature Request, Security Issue, Performance, Documentation) with counts and share; "Most requested" list showing each feature request with request count and distinct customer count; an "Immediate attention" callout strip for high churn risk and security items.
- **Long form** — the full narrative report: executive summary, per-category deep dive with representative quotes, churn-risk analysis, and recommended actions. Streams in as it is generated.

## Main panel — bottom: categorized evidence

Sortable, filterable table of every synthesized feedback item:

| Customer | Product | Category | Description | Churn risk | Confidence | Source |

- Inline filter chips for category, churn risk (N/A / Low / Medium / High), confidence (High / Low), and source channel (Support ticket / Email / Slack).
- Churn risk and confidence rendered as color-coded badges from semantic tokens.
- **Citation** — each row links to its originating item; clicking opens a side drawer showing the raw ticket/email/Slack message with channel, author, timestamp, permalink, and the excerpt the synthesis drew from. Multi-source items list every citation.

## Data

Mock dataset in `src/data/`: ~6 products across 3 product lines, ~20 customers, ~150 raw source items (tickets, emails, Slack messages) with realistic text, timestamps, and channel metadata. Filters and rollups compute client-side from this dataset, so every control genuinely changes the numbers.

## AI synthesis

A server function (`src/lib/synthesis.functions.ts`) receives the filtered raw items and returns structured output: per-item category, description, churn risk, confidence, and citation IDs, plus the summary rollups and the long-form narrative. Uses Lovable AI (`openai/gpt-5.6-sol`) via the AI SDK; the key stays server-side. Deterministic fallback rollups render if the model call fails, and 429/402 surface as clear in-app messages.

## Design

Clean modern SaaS: airy light surface, card-based sections, generous spacing, one confident accent color and a restrained risk palette (amber/red) reserved for churn and security signals. All colors as semantic tokens in `src/styles.css`; no hardcoded color utilities. Dashboard lives at `/` and replaces the placeholder index, with its own SEO head metadata.

## Technical notes

- TanStack Start routes; dashboard at `src/routes/index.tsx`, components under `src/components/dashboard/`.
- Filter state held in one hook (`useDashboardFilters`) and shared by sidebar, summary, and table.
- AI call is a `createServerFn` in a client-safe path; `LOVABLE_API_KEY` read inside the handler only.
- Schedules persist to localStorage in this version — swapping to Lovable Cloud later is a storage-layer change only.
